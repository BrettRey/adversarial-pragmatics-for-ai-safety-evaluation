Key finding up front: **the abstract inside the LaTeX source is already a fully updated v3.** `adversarial-pragmatics-for-ai-safety-evaluation.tex` lines 24-30 carry an abstract that has been through the same revision passes as the rest of the paper (see `DECISIONS.md` 2026-07-22 "Gelman pass" and 2026-07-23 entries, which explicitly note the abstract was updated then left alone). ## 1. Diff analysis: v2 abstract vs. current manuscript

**Para 1** ("Safety evaluations... unstable evaluator judgments.")

**Para 2** ("This paper introduces adversarial pragmatics as a benchmark and annotation protocol for evaluating model behaviour under instruction conflict, embedded commands, quotation, scope ambiguity, deixis, indirect speech acts, and multi-turn agent transcripts.")

- **Overclaim, confirmed false as worded:** listing "multi-turn agent transcripts" as something the paper already evaluates. The taxonomy chapter states plainly that this family "is instantiated only by a single-turn tool-result injection (pair P007); multi-turn transcript items are deferred to Study B" (`sections/03-taxonomy.tex:82`, the section's last sentence). The current in-paper abstract already corrects this: "It's designed to extend to multi-turn agent transcripts, which the seed set represents only by a single-turn tool-result contrast" (`adversarial-pragmatics-for-ai-safety-evaluation.tex:27`). v2's phrasing reads as if multi-turn transcripts are already in the benchmark; they aren't.
- **Undersold:** v2 calls it "a benchmark and annotation protocol." The title and every section now frame three components: a diagnostic framework, a seed benchmark, and an annotation protocol (title, and `adversarial-pragmatics-for-ai-safety-evaluation.tex:27`). The "framework" piece, the four-bearer projectibility decomposition (below), is the paper's stated principal claim (`sections/01-evaluation-problem.tex:65`: "That typed decomposition, not the pass/fail label it replaces, is the paper's principal claim").
- **Missing a family:** the taxonomy now names eight families explicitly (`sections/03-taxonomy.tex:11`), including "authority and instruction hierarchy" and "policy-boundary ambiguity" as distinct entries. v2's list conflates the first into "instruction conflict" and omits policy-boundary ambiguity entirely.

**Para 3** ("The contribution is empirical and methodological: a linguistically controlled taxonomy, an 18-item seed benchmark with validator-enforced metadata, a 54-row local seed pilot, an expert-evaluation protocol distinguishing task success, policy compliance, safety risk, refusal outcome, and evaluator confidence, and metrics for judge validity, diagnostic ambiguity, and taxonomy drift.")

- 18-item benchmark and 54-row pilot: both still accurate. Verified in `sections/04-benchmark-construction.tex:12` ("18 development items") and its Table (`sections/04-benchmark-construction.tex:32-61`, `\label{tab:seed-inventory}`); and `sections/06-experiments.tex:7` ("This produced 54 item--model outputs").
- **Undersold, protocol fields:** the current protocol's field list is bigger than v2's. `sections/06-experiments.tex:9` lists task success, policy compliance, safety risk, risk type, refusal outcome, failure attribution, confidence, and rationale. v2 omits failure attribution and risk type entirely, and failure attribution is now load-bearing: `sections/05-annotation-rater-roles.tex:11` splits it into four separate fields (observable signature, failure locus, causal attribution, evidential status) precisely because the pilot mislabeled a resolved-ambiguity row as `capability_failure` (the P005 case, `sections/06-experiments.tex:45-47`).
- **Undersold, metrics:** "metrics for judge validity, diagnostic ambiguity, and taxonomy drift" captures 3 of the 8 metric families defined in `sections/07-metrics.tex` (pairwise contrast accuracy, instruction-source sensitivity, mention/use robustness, scope/reference robustness, refusal calibration, judge-derived-interpretation validation, adjudication stability, taxonomy drift/diagnostic ambiguity), and says nothing about the "four projective targets" framing that organizes them (`sections/07-metrics.tex:57-63`).
- **The real gap:** v2's closing sentence of this paragraph, "The benchmark treats labels as inference licenses: it tests whether safety-relevant categories project across paraphrase, wrapper, model, and judge condition," blends what the manuscript now treats as four distinct, independently-failing bearers. The current in-paper abstract states this precisely: "the regime-relative reference, configured-system behaviour, the interpretation of evaluator outputs, and taxonomic assignment" (`adversarial-pragmatics-for-ai-safety-evaluation.tex:29`), each with its own warrant (`sections/01-evaluation-problem.tex:16-18`, `sections/07-metrics.tex:57-63`). This bearer-typing is arguably the single biggest conceptual addition since v2 and is entirely absent from it.

## 2. Drafted v3 abstract (full length)

Plain text, no LaTeX macros, no citations. **1916 characters** (arXiv limit 1920; v2 was 1461).

```
Safety evaluations for language models increasingly depend on judgments about ambiguous natural-language behaviour: whether a model followed an instruction, refused appropriately, complied with a policy, or misreported progress in an agentic task. Existing benchmarks compress these into pass/fail labels, obscuring whether failures reflect capability limits, policy ambiguity, instruction conflict, scaffold failure, or unstable evaluator judgments.

Adversarial pragmatics is safety-relevant model behaviour under instruction conflict, embedded commands, quotation, scope ambiguity, deixis, and indirect speech acts. It's designed to extend to multi-turn agent transcripts, but the seed set represents that family with a single-turn tool-result contrast.

This paper introduces a diagnostic framework, an 18-item seed benchmark, a 54-row pilot, and a six-cell LLM-judge assessment, with a protocol keeping task success, policy compliance, risk, refusal, attribution, and confidence analytically separate. The benchmark separates four inference targets a single label can conceal: the regime-relative reference, configured-system behaviour, evaluator-output interpretation, and taxonomic assignment. Its intended use is diagnosis, not deployment certification, vendor ranking, or a general safety score.

A first LLM judge that graded its own outputs with the expected answer visible missed the safety-relevant minority classes. Item-clustered intervals leave four of six chance-corrected agreement statistics unable to rule out a constant labeller, and hierarchical pooling shrinks the one eye-catching rubric effect toward the group mean and widens its interval through zero. Rejudging the objects across three judge models and two information conditions leaves the pattern intact: no cell recovers more than two of eleven partial successes, and the strongest cell's edge comes partly from never using that label.
```

## 4. Flags: claims at risk of overstating the evidence

1. **"designed to extend to multi-turn agent transcripts"**. This is the paper's own stated design intention (`adversarial-pragmatics-for-ai-safety-evaluation.tex:27`), not a delivered result. I kept the parenthetical/clause correcting it in both drafts, matching how the paper itself hedges it, but an arXiv reader skimming only the abstract's first clause could still read "designed to extend" as "already covers." Consider leading with the limitation instead of trailing it if this risk matters more than flow.
2. **"the strongest cell's edge comes partly from never using that label"**. Accurate (`sections/06-experiments.tex:134`) but "edge" is compressed from "aggregate advantage"; a reader could take "edge" as endorsing the cell as genuinely better rather than as an artifact of collapsing a three-way distinction into a binary. The paper is emphatic this is not a real advantage; the qualifier "comes partly from" is meant to preserve that, but it's worth Brett's eyes given how load-bearing this finding is.
3. **Field-list compression**. The phrase "risk, refusal, attribution, and confidence" (full draft) silently drops "risk type" and "rationale" from the fuller list at `sections/06-experiments.tex:9`. Not a false claim, but a reader comparing the abstract line-by-line against Section 5/6 will not find an exact 1:1 match.
4. **Omitted material**. The six-benchmark comparator table, the P005/P008 reference-review caveats, the "joint pair completion" naming rationale (nine pairs, all change response act), and the specific model names (`glm-4.7-flash`, `mistral:7b`, `mistral-small:24b`) are all confirmed-real but cut for space. If Brett wants any foregrounded, something else in the 1916-character draft has to go; there's essentially no headroom left under the 1920 limit.
5. **No explicit "24 billion parameters"**. I deliberately did not gloss `mistral-small:24b` as a parameter count anywhere, since the manuscript's own text never states this and doing so would be reconstructing a fact from memory rather than reading it from the source, which the task instructions rule out. If Brett wants the model's scale named, that number needs to come from an authoritative source he supplies, not from me.
6. **Study A / Study B silence**. Like the current in-paper abstract, neither draft names Study A or Study B or states they haven't run yet. This matches the existing (already-revised) in-paper abstract's own choice, not an omission I introduced, but flagging it since `sections/07a-limitations-next-steps.tex` is emphatic that no Study B results exist yet, and a v3 abstract is the kind of thing a reader treats as the full state of play.
